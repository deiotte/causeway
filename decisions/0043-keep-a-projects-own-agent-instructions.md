## Context

`sync.sh` wrote four agent-instruction files into a consuming project and owned all of
them outright. `AGENTS.md` is the standard itself, vendored and checksummed. `GEMINI.md`,
`.github/copilot-instructions.md` and `.cursor/rules/causeway.mdc` are shims that point
each tool at it. Every sync replaced all four, whatever the project had there. Issue #10
reproduced the result in a disposable project: its own Gemini instructions were gone
after one sync, and nothing said so.

`CLAUDE.md` was the one exception — seeded once, never overwritten — and that exception
had the opposite failure. A project that already had a `CLAUDE.md` kept it, and nothing
checked that it imported the standard. The sync succeeded, the lock was written, the
drift check passed, and no instruction any agent read mentioned Causeway.

ADR 0042 made a refused install change nothing. This ADR is about the install that
succeeds.

## Forces

- **Agent instructions are a project's own content.** Instructions are where a team
  records what its agents get wrong. Replacing them destroys the most local knowledge in
  the repository with no record of the loss — the failure the Practitioner floor exists
  to prevent, done by the installer.
- **`AGENTS.md` has to be the standard.** The gate, `check-drift.sh`, every adapter and
  every project `CLAUDE.md` name it. Moving the vendored copy would change all of them,
  and the standard's own text tells drifted projects to re-sync to restore it.
- **The shims are pointers, and a pointer can share a file.** Each shim is a few
  paragraphs telling a tool to read `AGENTS.md`. Nothing about that needs the whole file.
- **A re-sync must be a no-op.** Anything that appends has to recognize what it appended
  last time, or the second sync duplicates it.
- **Recognizing "ours" needs evidence.** The lock records `AGENTS.md`'s checksum, so a
  previously synced copy is provable. The shims were never in the lock, and this
  repository's history starts at the public release (ADR 0039), so only the current shim
  text is known.

## Decision

**`AGENTS.md`.** An existing `AGENTS.md` is Causeway's when the previous
`.causeway-lock` lists it, or when it is byte-identical to the standard being installed.
Then it is replaced; if its checksum differs from the one the lock recorded, the sync
warns that the edit was drift and has been restored. Anything else is the project's own
file, and the sync refuses with exit `9`. The refusal names the file and gives the move:
`mv AGENTS.md AGENTS.project.md`, re-run, import both from `CLAUDE.md`. The refusal
happens in ADR 0042's plan phase, so it changes nothing.

**The three shims own a marked section, not the file.**

```
<!-- causeway:begin — managed by Causeway tools/sync.sh. ... -->
(the shim)
<!-- causeway:end -->
```

| The file already… | The sync |
|---|---|
| does not exist | writes it holding only the section (the `.mdc` keeps its frontmatter first) |
| is byte-identical to the current shim | treats it as an earlier sync's copy and writes exactly what a fresh install writes |
| has one begin marker before one end marker | replaces what is between them and nothing else |
| has no markers | keeps it byte for byte and appends the section |
| has any other number or order of markers | refuses, exit `9` — guessing where a section ends is how a sync deletes somebody's instructions |
| is a symlink resolving to `AGENTS.md` | leaves it alone; the tool already reads the standard |

When an appended-to file carries the old `GENERATED by tools/render-adapters.sh` line,
the sync says it may hold an older shim the project never edited, and that the old text
can be deleted.

**`CLAUDE.md`** is still never edited. When the project's own `CLAUDE.md` has no
`@AGENTS.md` import line and is not a link to `AGENTS.md`, the sync warns and prints the
line to add. The warning claims only that the reference is missing. A reference being
present does not show that an agent read it — Build DNA open item 9.

`CLAUDE.md.causeway` is a reference copy no tool reads, under a name only Causeway uses,
and is still replaced every time.

## Alternatives considered

- **Refuse on any existing shim.** Safe, and it would block nearly every real adoption,
  because a project with agents already has a `GEMINI.md` or Copilot file. The section
  keeps the content and still installs the pointer.
- **Append to `AGENTS.md` too.** Then `AGENTS.md` is no longer the standard, the lock
  cannot checksum it, and `check-drift.sh` cannot tell an edit from an addition. The
  standard has to be a whole file. The project's text moves instead.
- **Vendor the standard somewhere else and let the project keep `AGENTS.md`.** The right
  long-term answer for tools that read only `AGENTS.md`, and a change to every pointer,
  the gate's inputs and every adopting project's imports. Not decided on one issue's
  evidence; the refusal keeps the choice open without losing anything meanwhile.
- **Insert the `@AGENTS.md` line into `CLAUDE.md`.** `CLAUDE.md` is the file the
  standard promises never to touch. A warning with the exact line costs the project one
  edit; breaking the promise costs the promise.
- **Record shim checksums in the lock to recognize older copies.** Only helps from the
  next release on, and markers do the same job from now on without a new lock field.
  Shims from before the public history are not recognized; they are kept as project
  text with the section after them, which loses nothing.

## Consequences

A fresh install's shims now carry the markers, so their bytes differ from v2.3.1's. A
project that synced since v2.2.0 holds the bare current shim and upgrades to exactly a
fresh install's file. An older shim is kept as project text with the section after it,
and the sync says so.

A project whose own `AGENTS.md` was silently replaced before is now refused instead.
That is the one install that used to succeed and now does not, and it is the reason
this release is minor, not patch.

`ADOPTING.md` gains the steps for installing over existing instructions and for
recovering files a pre-2.4.0 sync overwrote, from version control.

## Evidence

- `tools/test-sync.sh`: 32 passed, 0 failed. The fifteen cases this ADR adds cover a
  project's own `AGENTS.md` (refused, target byte-identical); customized Gemini,
  Copilot and Cursor files (original bytes kept as a prefix, one section, pointer
  present); `CLAUDE.md` unchanged and its missing import reported, and not reported once
  added; a second sync byte-identical; an edit inside the section replaced while one
  outside is kept; damaged markers refused; bare shims upgraded to a fresh install's
  bytes; a `GEMINI.md` symlink to `AGENTS.md` left a link; an edited vendored
  `AGENTS.md` restored with a warning.
- With v2.3.1's `sync.sh` swapped in, ten of those fifteen fail.
- `tools/validate.py`, `build-bundle.sh --check` and `render-adapters.sh` pass.
